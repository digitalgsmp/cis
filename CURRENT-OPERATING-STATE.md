## How Eric should use ChatGPT and Claude Code today

There are really **three** parties now, not two — and it matters which one you're talking to.

### ChatGPT (the chat app you type into)
Use it for: planning, deciding what should happen next, and interpreting results in plain English. It does **not** have any live connection into your repository, database, or running container. To give it current project state, you (or the tooling on your behalf) hand it a set of exported context files — confirmed freshly regenerated today — which you then upload into the chat yourself. That upload step has **not** gone away. It does not do the file-level independent code review described below; that's Codex's job (next).

### Codex (a separate command-line review agent, not the ChatGPT chat window)
This is what actually reviews Claude's work: it reads the real changed files, checks them against recorded hashes, and writes an independent PASS/FAIL verdict. In this last stretch of work, Codex reviewed and PASS/FAIL-graded essentially everything Claude built (the workbench, Card Factory, Card Runner, the UI, and the continuity mechanism itself) and also wrote several of the correction/scoping cards (e.g., the CARD 6R audit that reclassified some of WB.1's loose ends). Codex and Claude Code hand work back and forth through the same host-continuity tool — **without you relaying anything between them.**

### Claude Code
Use it for: reading the actual repository, implementing approved cards, running commands on the host, running tests, inspecting live state (databases, running containers, the queue), and writing the evidence files that Codex then reviews. This is the "implementer" role throughout — every workbench/Card-Factory/Card-Runner piece above was built this way.

### Manual relay — what's still on you vs. what's automatic
**Still on you:** uploading fresh context packets to the ChatGPT chat app when you want it to weigh in; deciding what happens next when there's a real product choice to make (e.g., which of the "next task" candidates below to pursue); and approving anything that touches money, secrets, or a live/production change (paid model calls, activating the new workbench, applying the staged database migration, restarting the container).

**No longer on you** (the host now handles it, specifically for Claude ↔ Codex): relaying cards between them, copying Claude's results over for review, carrying independent-review results back, and remembering what happened in an earlier session so it isn't lost. That's exactly what the tool that just finished closing WB.1 does — it keeps a running, timestamped record both agents read from and write to. You should no longer need to paste Claude's output into a Codex session or vice versa. This does **not** extend to the ChatGPT chat app itself — that leg is still manual, as above.

## What do I do when…

**A. "I have a new idea or change I want CIS to make."**
Bring it to either agent — most naturally ChatGPT/Codex, since its job is to scope and coordinate. It gets added to `docs/UNIFIED_BUILD_LIST.md` (the one queue) rather than a new document, and gets shaped into a bounded card before Claude touches any code.

**B. "Claude says implementation is finished."**
Nothing is ever accepted on Claude's own word — that's a hard rule (CLAUDE.md: "No completion is accepted from self-report"). Claude writes `completion.json` (status `READY_FOR_VERIFICATION`, never "verified") plus its evidence. Codex independently reviews the actual changed files and writes a separate `verification.json` with a real PASS/FAIL — this is a file-by-file check, so it's Codex's job specifically, not something the ChatGPT chat app does. You don't have to shuttle these files between Claude and Codex yourself — the continuity tool makes the result visible to the other agent without you relaying it. What stays with you is the decision of whether the finished piece should go live (see D), and whether to loop ChatGPT in on the outcome.

**C. "ChatGPT (or Codex) finds a problem."**
It's recorded as a "discovery" through the same tool — classified as fixed immediately, fixed before the stage can close, or explicitly deferred to a named, real, future queue item (never a vague "later"). This just happened live: Codex's file-level audit reclassified three of WB.1's own loose ends this way in the last day. This part is structurally recorded now, not just chat prose — you can trust that a raised problem doesn't quietly vanish. If instead it's ChatGPT that raises a concern in a planning conversation, that goes back in the same way a new idea does (see A) — you carry it over and it becomes a queue item or a card correction.

**D. "The work passes review."**
The stage can only be marked closed through a deterministic check (`close-task` / `closeout-check`) that independently re-derives whether everything is actually clean — it refuses and writes nothing if a blocker remains. Nobody "declares" a stage done by saying so. Recording completion is the continuity tool's job; deciding to actually flip something on in production (like switching the browser over to the new workbench) is still your call, separate from the record-keeping.

**E. "I just want to know what we should work on next."**
`docs/UNIFIED_BUILD_LIST.md` is the only authoritative source — not chat memory, not an old NEXT-CARD file, not this session's history. See "Next authoritative task" below for what it currently says.
