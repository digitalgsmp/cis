This is an important clarification that changes the priority order after Tier 7. Let me break it down.

What you're actually describing

You have approximately 1,367 session files in the archive. Those files contain your own words — your reasoning about how the social worker app should work, decisions you've already made, problems you've already solved, patterns you've already established. Right now that knowledge is inaccessible. Every new session starts blind. You re-explain things you've already worked out. Models make suggestions that contradict decisions you made six months ago because nobody can see those decisions.

What you need is: ask a question, get back the relevant excerpt from your own archive in your own words, with enough context to know when and why it was said.

That's the actual capability gap. Everything else is infrastructure serving that goal.

On the NeMo/Research gateway problem

You're right that it's been underperforming. NeMo's behavioral firewall was designed to block the Research gateway from guessing or hallucinating current facts — force it to use Tavily web search instead. But if web search was never properly configured in Hermes, the Research gateway has been blocked from guessing AND blocked from searching, leaving it able to do almost nothing useful. That's not a useful agent — it's a gate with no exit.

This needs to be confirmed: does Hermes have a working web search integration right now? If Tavily was never wired, the Research gateway is effectively disabled for its primary purpose. That's a blocker for the archive retrieval use case too, because Research is the profile that's supposed to ground queries in evidence.

How this affects the router and the tier sequence

Tier 7 as proposed routes structured work into a Kanban pipeline. That's still the right architecture. But the pipeline's Research stage — the first stage every substantive task goes through — currently can't search anything external or internal. It can only work with what's in AGENTS.md context.

For archive retrieval to work, you need:

First, the archive indexed. The 1,367 session files need to be importable and searchable. That's the transcript import work from the Foundation Plan (currently classified as deferred-unscheduled) plus Chroma/VDB at Tier 9. But Chroma is overkill for a first pass — a flat SQLite FTS5 table over the session files would give you lexical search in your own words immediately, without vector infrastructure.

Second, the Research gateway needs a working retrieval tool. Either web search (Tavily) for external facts, or an internal search endpoint for the archive, or both. Without at least one of these, the Research stage of the pipeline produces nothing useful.

Third, the router needs to know when a query is asking about archive content vs asking for new work. That's a classifier signal — "what did I decide about X" routes to archive retrieval, "design Y" routes to the drafting pipeline.

What this means practically for sequencing

Tier 7 (Router Reclassification) still makes sense as specified — it wires the router to the pipeline and that infrastructure is needed regardless. But between Tier 7 and Tier 8, there's a prerequisite that isn't currently scheduled:

Fix the Research gateway — confirm or establish working web search in Hermes, and determine whether NeMo's blocking behavior is helping or just creating a dead end.

Then before Tier 8 (MCP Bridge), import the archive into a searchable form. FTS5 over session files is a realistic Tier 7.5 — self-contained, no vector infrastructure required, immediate value. You ask "how did I say the intake form should work" and get back the session excerpt where you said it.

The social worker app can't be built without that retrieval capability. Not because the code is hard, but because the decisions about how it should work are locked in those archives. Without retrieval, every design session starts from scratch and risks contradicting prior decisions.

The direct answer to your question about the router

Tier 7 as proposed doesn't need to change based on this. The router's job is to classify intent and dispatch to the right pipeline stage. Whether the Research stage behind it uses web search, archive retrieval, or both is a Research gateway concern, not a router concern. The router just needs to know that "archive" queries exist as a signal class — and that's a classifier addition, not a router architecture change.

What should change is the work scheduled after Tier 7. The current sequence is Tier 7 → Tier 8 MCP Bridge → Tier 9 Chroma/VDB. Given what you've described, a more useful sequence is:

Tier 7 → Fix Research gateway (web search confirmation) → Tier 7.5 Archive import + FTS5 search → Tier 8 MCP Bridge → Tier 9 Chroma/VDB

That gives you access to your own archive before you build the social worker app, which is when you actually need it.
