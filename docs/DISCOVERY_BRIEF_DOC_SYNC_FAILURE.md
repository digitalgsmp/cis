# Discovery Brief: Documentation Synchronization Failure

**Prepared for:** External advisor deliberation (Claude, ChatGPT)
**Date:** 2026-06-19
**Status:** Open — requires architecture decision on fix approach

## Problem Statement

After a session that settled a major architecture decision (three-layer process isolation, Docker containment verified, /opt/cis-control enforcement layer), the generated documentation (AGENTS.md, all 11 HCP files) and the hand-maintained DEV-PIVOT docs do not reflect this decision. A fresh Hermes session reading these files will have no knowledge of today's work.

This is not a one-time omission — it's a structural gap in the session-to-spine write path that causes every session's decisions to accumulate only in transcripts and handoff prose, never in the authoritative DB that the generators read.

## Root Cause Analysis

### Cause 1: No automated session-to-spine write path
When an architecture decision is reached in conversation, no hook or process writes it to the spine. The spine is only updated by explicit pipeline runs (state_write.py, Eric gate approvals, migration scripts). Ad-hoc session decisions are orphans — they live in transcripts and handoff files but never enter the authoritative DB.

### Cause 2: project_state schema is single-purpose
The `project_state` table only tracks `build_phase` (key='build_phase'). There's no key for `enforcement_architecture`, `active_decision`, `current_direction`, or `session_summary`. Adding today's decision requires either a new key convention or a separate mechanism.

### Cause 3: Next Actions section depends on build_plan_nodes
The generator queries `build_plan_nodes WHERE status IN ('PENDING','IN_PROGRESS')`. When all nodes are COMPLETE or DEFERRED, the section is blank — even though real next actions exist. The "Do Not Start" list (Section 2) is hardcoded in `agents_static.yaml` and doesn't come from the DB at all.

### Cause 4: DEV-PIVOT docs are hand-maintained with no regeneration
Unlike HCP files and AGENTS.md, the 16 DEV-PIVOT docs are static markdown. They can only be updated by an agent writing new files or editing existing ones — there's no generator.

### Cause 5: Handoff files are generated from the spine
`HCP_07_RECENT_HANDOFF.md` is generated by `generate_hcp.py` from the spine. If the spine doesn't have today's decisions, the generated handoff won't either. The `docs/SESSION_HANDOFF_2026-06-19.md` I wrote manually is outside the generation pipeline — it won't appear in regenerated HCP output.

## Question for Advisors

How should CIS close the session-to-spine gap so that:
1. An architecture decision reached in conversation is durably recorded in the authoritative DB
2. The generators (generate_all.py, generate_hcp.py, generate_agents_md.py) produce output that reflects current decisions
3. Fresh sessions start with accurate context without manual handoff-file injection
4. The solution doesn't require the enforcement primitive to already exist (chicken-and-egg: we're building the primitive because the system can't be trusted; but we need the system to record the decision to build the primitive)

Specifically:
- Should `project_state` get new keys for direction/architecture decisions?
- Should a `session_closeouts` row carry today's decisions to the generators?
- Should `build_plan_nodes` get new PENDING entries for the enforcement primitive work?
- Should DEV-PIVOT docs be brought into the generation pipeline (a template + spine data)?
- Or is the handoff-file pattern (docs/SESSION_HANDOFF_*.md) the correct fallback, and the fix is to ensure the generators include handoff files?
