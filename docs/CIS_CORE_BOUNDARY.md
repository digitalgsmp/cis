# CIS Core Boundary
Version: 1.0
Date: 2026-05-26
Authority: Eric (Architect)
Status: APPROVED — do not modify without Eric's explicit instruction

---

## What CIS Is For

Supply the world's information through research and training data to develop
ideas into completed projects, tracked and executed by priority and schedule,
and deliver the tool, product, or content desired — working through CIS
processes.

---

## What CIS Must Do When Complete

1. **Retrieve prior work** — When a problem has been examined before and a
   solution chosen, CIS must be able to find that session, that reasoning,
   and that decision on demand. No re-litigating solved problems.

2. **Maintain shared context** — Every model that participates in a session
   must start with the current objective, the current system state, and the
   vision — not a blank slate. Context must load automatically, not manually.

3. **Capture without derailing** — When a new issue, idea, or problem is
   discovered mid-session, CIS must capture it immediately and return to the
   current task. Discovery must not become a detour.

4. **Track decisions and delivery** — What has been decided, what has been
   built, what has been verified, and what is next must be visible and current
   at all times. No assumption about state — only verified state.

5. **Deliver completed work** — CIS exists to produce finished tools,
   products, and content. Process is not the output. Delivered work is the
   output.

---

## What CIS Will Never Do

1. **Act on assumptions over provable information** — If the current state of
   something is unknown, CIS must say so and find out. It must never fill gaps
   with inference and proceed as if verified.

2. **Chase quick fixes at the expense of the mission** — A branching problem
   discovered mid-session is not the new priority unless Eric explicitly
   changes focus. Every fix must be evaluated against whether it serves the
   current objective.

3. **Let process replace delivery** — Governance, documentation, specs, and
   planning are tools. They are not the work. CIS must not produce more
   infrastructure for managing infrastructure. Each process artifact must
   directly enable a delivery.

---

## What Is Out of Scope for CIS Core

The following are real future capabilities but are not part of CIS Core.
They do not get built until the five core capabilities above are working and
verified:

- Full public product packaging or distribution
- Full DAM (Digital Asset Management) beyond basic asset tracking
- Full LMS beyond course content already in the database
- Full creative project management suite
- Automated multi-agent autonomy without human approval gates
- Pass 5 implementation (project promotion) until safety gates are cleared
- Unified memory across all advisor models
- Discord/Telegram gateway messaging

---

## The Single Most Important Capability

Being able to find the documents where solutions have been examined in detail,
remedies worked out, and a choice made.

Everything else serves this. If this does not work, nothing else matters.

---

## Definition of Done for CIS Core

CIS Core is working when:

Eric can ask "have we solved this before" and receive back the specific
session or document where it was worked out, with the reasoning intact,
in less than thirty seconds.
