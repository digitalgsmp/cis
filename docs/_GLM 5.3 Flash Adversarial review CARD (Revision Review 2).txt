Adversarial review: CARD reviewer-readonly-and-reconciliation
What the card fails to establish
1. The static evidence inspects the files that don't enforce. All six greps run against the profile YAMLs and advisor_review.sh. The thing actually enforcing read-only is the pre_tool_call hook ("THE WALL"), whose configuration is never grepped, catted, or verified. Worse, the evidence is self-contradictory: the CLARITY section says the hook "must be configured to DENY write_file" — if that configuration lives in the profile YAML, the deny entry names write_file, so grep -c "write_file" advisor.yaml returns ≥1 and the evidence fails on a correct implementation. If the hook config lives elsewhere, the greps only prove the profile doesn't grant write_file — which says nothing about whether the hook actually denies it, is loaded, or is bypassable. Both branches of the fork are broken: the check is either wrong or vacuous.

2. The write-block behavioral test cannot distinguish enforcement from compliance. "Ask advisor to write a file → blocked with a stated reason" passes if the model simply declines and says something reason-shaped. An implementer under pressure can add "You are read-only; refuse writes" to the reviewer's system prompt, never touch the hook, and go green. The test never checks that a tool call was attempted and intercepted — no requirement for a deny entry in a hook log, no requirement that the stated reason match the hook's configured denial, no check that the target file is absent. For a card whose entire premise is Eric's complaint that enforcement was theater, the acceptance test for enforcement is itself theater-able.

3. The terminal policy is a blacklist of examples, not a stated default-deny. The clarity note denies rm, mv, redirect, chmod — but a reviewer that can execute commands can write via tee, cp, sed -i, git apply, git stash, truncate, python -c 'open(...)', dd, install… Is the terminal allowlisted (default-deny) or blacklisted (default-allow)? The card never says, and the DONE-WHEN ("cannot write, patch, or delete any file") is far stronger than the enumerated deny list. Same hole for dispatch: cis_dispatch is grepped, but if terminal isn't default-deny, a reviewer can start a run by invoking the pipeline CLI directly, never touching cis_dispatch. Also unaddressed: whether subagents spawned by a reviewer inherit the profile (a spawned agent with the default profile walks around the wall entirely), and whether sqlite3 access is opened read-only (mode=ro/immutable) — plain sqlite3 creates -wal/-shm and permits ATTACH/PRAGMA side effects, which violates "cannot write any file" on a technicality that matters.

4. Round-1 independence is asserted but unverifiable — and structurally undermined by the un-blinding. The card makes reviewers maximally readable (that's the point) but never requires round-1 outputs to be staged somewhere the other lineage can't read them before the cross-feed step. Both reviewers can ls/cat the shared reviews directory; "independence first" is then a convention, not a property. No timestamp, ordering, or staging-isolation evidence is required.

5. The reconciliation evidence contradicts the reconciliation done-when. DONE-WHEN 5: what reaches Eric is "the reconciled result… not two independent opinions." Behavioral evidence: "final artifact contains BOTH lineages' findings side by side." Side-by-side raw findings is two independent opinions. Nothing requires the artifact to contain the actual reconciled structure — per-lineage agreements, disagreements, what-each-thinks-the-other-missed. And the grep for reconcil|cross-feed|other lineage in the script is satisfied by a comment — in a codebase the card itself flags as already containing reconciliation-shaped dead code (sequential_review). String presence is anti-evidence here; the project has demonstrated that already.

6. The evaluator is never behaviorally tested. All three behavioral items say "advisor." The evaluator (8650) gets greps only. An evaluator with intact write and dispatch passes every check in this card.

7. Eric's actual complaint never becomes an acceptance criterion. The source quote is that the review is fraud because the reviewers cannot measure anything. The response is visibility plus non-interference. The strongest capability done-when is "read a file and quote its contents back" — reading, not measuring. No requirement that a reviewer can pull a fact from the spine's run records and cite it; no enumeration of which artifacts the reviewers must be able to see for the review to be un-blinded where it matters (the read test works fine against a README). Token-cost measurement is explicitly deferred. The card can close with Eric's fraud complaint fully intact in substance.

8. Out-of-scope seams make two done-whens unverifiable. The enforcement primitive (ADR-015/016) is out of scope and gated elsewhere — so DONE-WHEN 2 and 3 depend on a component this card cannot verify and doesn't declare as a blocker; the only path to green if the primitive isn't landed is the fake from gap 2. The Eric Gate is out of scope — so "what reaches Eric" can never be tested end-to-end; the card can only show an artifact exists somewhere.

9. A read-only reviewer can't persist findings — who writes them? Presumably the harness captures and writes on the reviewer's behalf, but the card never says so, leaving "cannot write any file" ambiguous (via its own tools? at all?).

Results that satisfy the card while being wrong
Prompt-level read-only. System prompt tells the reviewer to refuse writes; it declines politely with a stated reason; all greps and behavioral checks green; THE WALL is broken or absent. The reviewers can write the moment they're persuaded to — Eric's problem, now cosmetically patched.
Blacklist leak. Hook denies the six named verbs; reviewer writes via tee or git apply or a subagent. The write test (which calls write_file) still passes.
Reconciliation theater. Script gains a # reconcile comment; the "reconciled" artifact is two raw transcripts concatenated; the evaluator saw the advisor's findings from round one (independence never existed). Eric receives two opinions labeled as one — the exact fraud, re-branded.
Hollow un-blinding. Read test passes on a known trivial file; the spine query returns nothing useful; reviewers still can't measure anything the review requires.
Capitulation. Cross-feed runs; the second lineage agrees with everything; "disagreements: none." Format satisfied, information added: zero.
Verdict: demand changes
The intent is sound and the CLARITY section shows real understanding of the actual traps (bundled read+write toolsets, dead-code precedent, independence-before-reconciliation). But the evidence layer cannot detect the card's own primary failure modes, and one check likely fails a correct implementation while passing broken ones. Approving this would recreate Eric's "fraud" with better paperwork — the worst outcome for a card whose purpose is restoring trust in the review. Required changes:

Grep the hook configuration for the deny entries (expect them present, with context), or drop the static greps in favor of behavioral-only evidence.
Write-block test must prove interception: a deny event in a hook log naming the tool, the model's attempt observed, target file absent, reason matching the hook's configured denial — not model prose.
State terminal policy as default-deny with an explicit allowlist, and test bypass attempts (tee, git apply, python -c, redirect, subagent spawn) plus dispatch-via-CLI.
Run all behavioral tests against both roles.
Read test uses a nonce file generated at test time; add a done-where establishing measurement (e.g., reviewer answers a question requiring a fact pulled from the spine's run records).
Independence evidence: round-1 outputs staged unreadable to the other lineage until cross-feed, with ordering shown. Reconciliation evidence: artifact must contain per-lineage agreement/disagreement/missed sections — resolve the contradiction with "side by side."
Either declare the card blocked on ADR-015/016 or scope DONE-WHEN 2/3 accordingly; reword bullet 5 to "produces the artifact designated for the Eric Gate," since delivery is out of scope.
Reject would be too strong — the fixes are cheap and the design instinct (behavioral-first, independence-then-reconcile) is right. But as written, green on this card means almost nothing.
